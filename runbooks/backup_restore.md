# Incident Runbook: Logical Backup & Isolated Database Recovery
**Incident ID**: INC-DB-003  
**Severity**: Sev-1 / Sev-2 Disaster Recovery  
**Target Environment**: `dba_lab` (Source) -> `dba_lab_restore` (Isolated Target)  
**Applicable Roles**: Application Support Engineer, Production Operations Lead

---

## 1. Scenario & Objectives
* **Scenario**: Disaster recovery simulation, major release rollback prep, or scheduled non-production refresh.
* **Goal**: Take a complete, consistent logical backup of the active schema without blocking production traffic, restore it to an isolated target, and cryptographically/mathematically verify data integrity.

---

## 2. Backup Execution Standard (Non-Blocking)

### Command Standard:
```powershell
mysqldump -u root -p `
    --single-transaction `
    --quick `
    --routines `
    --triggers `
    --default-character-set=utf8mb4 `
    --result-file="E:\project\MySQL DBA\backups\dba_lab_backup_YYYYMMDD_HHMMSS.sql" `
    dba_lab
```

### Key Technical Flags Explained (Interview Focus):
1. **`--single-transaction`**:
   * Issues `START TRANSACTION WITH CONSISTENT SNAPSHOT`.
   * Leverages InnoDB Multi-Version Concurrency Control (MVCC) and Undo Logs.
   * **Application Support Value**: Reads a point-in-time consistent view of the database without acquiring table-level read locks (`LOCK TABLES`). Web and API traffic can continue writing uninterrupted.
2. **`--quick`**:
   * Forces mysqldump to retrieve rows from the server row-by-row rather than buffering entire tables into client memory. Crucial for tables containing large JSON payloads (like `POL_POLICY_VER_V2`).
3. **`--result-file`**:
   * Directly writes pure binary UTF-8 stream to disk, preventing Windows PowerShell Unicode/UTF-16 encoding corruption.

### Measured Baseline:
* **Database Size**: 1.20 GB
* **Elapsed Time**: **24.99 seconds**
* **Throughput**: ~48 MB/sec logical write speed.

---

## 3. Safe Isolated Restore Procedure

### Production Rule:
**Never restore over the source database directly.** Always restore into a clean, isolated schema (`dba_lab_restore`) or a secondary instance.

### Command Execution:
```powershell
# 1. Create target container
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS dba_lab_restore CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;"

# 2. Stream restore via OS pipe (No OOM memory buffering)
cmd.exe /c "mysql -u root -p --default-character-set=utf8mb4 dba_lab_restore < dba_lab_backup_YYYYMMDD_HHMMSS.sql"
```

### Measured Baseline:
* **Restore Time**: **155.61 seconds** (~2.5 minutes for full 1.2 GB load).

## 4. Post-Restore Verification (Exact Counts vs. Statistics)

### Critical Technical Discovery:
In InnoDB, querying `information_schema.TABLES.TABLE_ROWS` returns **statistical estimates** generated by random index page dives, not exact counts. 

To prove 100% data fidelity, perform deterministic exact verification:
```sql
SELECT 'mas_agency' AS tbl, (SELECT COUNT(*) FROM dba_lab.mas_agency) AS src, (SELECT COUNT(*) FROM dba_lab_restore.mas_agency) AS dst
UNION ALL
SELECT 'mas_agent', (SELECT COUNT(*) FROM dba_lab.mas_agent), (SELECT COUNT(*) FROM dba_lab_restore.mas_agent)
UNION ALL
SELECT 'pol_policy_v2', (SELECT COUNT(*) FROM dba_lab.pol_policy_v2), (SELECT COUNT(*) FROM dba_lab_restore.pol_policy_v2)
UNION ALL
SELECT 'pol_policy_ver_v2', (SELECT COUNT(*) FROM dba_lab.pol_policy_ver_v2), (SELECT COUNT(*) FROM dba_lab_restore.pol_policy_ver_v2)
UNION ALL
SELECT 'qot_quote_v2', (SELECT COUNT(*) FROM dba_lab.qot_quote_v2), (SELECT COUNT(*) FROM dba_lab_restore.qot_quote_v2)
UNION ALL
SELECT 'ref_carrier_mapping', (SELECT COUNT(*) FROM dba_lab.ref_carrier_mapping), (SELECT COUNT(*) FROM dba_lab_restore.ref_carrier_mapping)
UNION ALL
SELECT 'sub_submission', (SELECT COUNT(*) FROM dba_lab.sub_submission), (SELECT COUNT(*) FROM dba_lab_restore.sub_submission);
```

## 5. Point-in-Time Recovery (PITR) Concept & Procedure
If data corruption occurred at `11:45:00`:
1. Restore the last full backup taken at `11:36:45` into `dba_lab_restore`.
2. Extract all transactions between `11:36:45` and `11:44:59` from binary logs using `mysqlbinlog`:
   ```bash
   mysqlbinlog --stop-datetime="2026-11-10 11:44:59" DESKTOP-U62AUH2-bin.000001 | mysql -u root -p dba_lab_restore
   ```
3. Stop precisely before the corrupting query, ensuring zero lost valid transactions.
